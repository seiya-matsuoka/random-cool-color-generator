# 画面設計

本書は [要件定義](01-requirements.md) に基づく画面と操作を定義する。
保存処理の内部仕様は [技術設計](03-technical-design.md) に従う。

## 1. 画面構成

- 画面は 1 ページとし、ルーティングを導入しない。
- タイトルは `Random Cool Color Generator` とする。
- UI は英語とし、表示中の色を主役にした白・グレー基調の明るい画面にする。
- 本文やボタンを生成色の上に直接重ねない。
  操作部は読みやすい中立色の面に配置する。
- デスクトップでは大きな正方形の色見本と、コード・日時・操作部を横に配置する。
  狭い画面では色見本、情報、操作の順に縦に並べる。
- その下に `History`、`Favorites`、保存に関する短い説明を配置する。
- `Details`、`History`、`Favorites` は初期状態で閉じる。
  開閉状態は保存しない。

```text
Random Cool Color Generator
A fresh cool color, with the details to keep it.

+-------------------+   #1D89E2                   [Copy HEX]
|                   |   Generated at: ... UTC+09:00
|    Color swatch   |   [Generate color] [Add to favorites]
|                   |   > Details
+-------------------+     RGB / HSL / SHA-256

通知・保存状態に関する案内

> History (件数 / 20)                  [Clear history]
> Favorites (件数 / 20)

ブラウザ保存に関する短い説明
```

図は情報の順序を表す。
ページ背景は slate 系の明るい中立色、主要領域は白い角丸のカードとする。
色見本と情報は `md` 以上で横並び、一覧の行は `sm` 以上で操作を横へ並べる。
それより狭い幅では縦に並べ、長い文字列と操作ボタンは折り返す。

## 2. メイン表示

| 項目       | 表示と動作                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| 色見本     | 現在の HEX を背景にした正方形。色がない場合は中立色のプレースホルダー                                       |
| HEX        | 大きく表示する。大文字の `#RRGGBB` とする                                                                   |
| 生成日時   | `Generated at` とともにミリ秒・UTC オフセット付きで表示する                                                 |
| 生成       | `Generate color`。生成中は `Generating...` と表示し無効にする                                               |
| お気に入り | 未登録は `Add to favorites`、登録済みは `Remove favorite`。登録状態が色やアイコンだけに依存しないようにする |
| コピー     | HEX の横に `Copy HEX` を配置する                                                                            |
| 詳細       | ネイティブの `details` / `summary` を基本とし、RGB、HSL、SHA-256 を表示する                                 |

- 日時の表示例は `2026-10-19 00:00:00.000 UTC+09:00` とする。
  保存済みの生成時刻を表示時のタイムゾーンで変換する。
- RGB の表示・コピー形式は `rgb(29 137 226)`、HSL は `hsl(207 77% 50%)` とする。
- 詳細内に `Copy RGB`、`Copy HSL` を配置する。
  ハッシュのコピー専用ボタンは設けない。
- SHA-256 は小文字 64 桁の全文を表示し、途中で省略せず折り返す。
- 表示値は通常のテキストとして選択可能にし、コピー API が使えない場合も手動コピーできるようにする。
- 履歴・お気に入りから選択した場合は、色、生成日時、詳細を同時に切り替える。
  再表示した時刻は生成日時に使用しない。

## 3. 履歴とお気に入り

### 3.1. 共通の一覧

- 見出しに現在の件数と上限 20 件を表示する。
- 1 行に小さな色見本、HEX、表示切り替え操作、お気に入り操作を配置する。
- 色見本と HEX を含む選択ボタンと、お気に入り操作のボタンを別の要素にする。
  ボタンの中に別のボタンを配置しない。
- 選択ボタンの操作名から、対象の HEX と、色を表示する操作であることが分かるようにする。
- 履歴で同じ HEX が複数ある場合も異なる記録として扱う。
  キーには記録 ID を使用する。
- 現在選択中の記録は記録 ID と HEX の両方で比較し、色だけで示さない。
  `Current record` の文字、枠・背景、`aria-current` で選択状態を示す。
  お気に入りの登録状態は HEX で比較する。
- 選択ボタンの操作名は `Show color <HEX> Current record, record <連番>` とし、選択中の補助テキストも含める。
  未選択行では `Current record` を含めない。
- React の key は履歴では記録 ID、お気に入りでは HEX を使用する。
- 一覧の選択で順序を変えたり、閉じている別の一覧を自動で開いたりしない。

### 3.2. History

- 空の場合は `No history yet.` と表示する。
- 各行から色の再表示と、お気に入りの登録・解除を行える。
- `Clear history` は見出しに隣接する独立したボタンとする。
  開閉用の `summary` の内部には配置しない。
- 0 件の場合は全件削除ボタンを無効にする。
- 正常保存中の全件削除は、確認後に保存済み履歴と画面の履歴を削除する。
- 保存障害によるタブ内だけの履歴を削除する場合は、確認文でその範囲を明示する。
  破損保護中の保存領域の削除には `Reset history` を使用する。

### 3.3. Favorites

- 空の場合は `No favorites yet.` と表示する。
- 各行から色の再表示と解除を行える。
- 上限に達した場合は `Favorites are full. Remove a color to add another.` と表示し、未登録色の追加ボタンを無効にする。
- 上限に達していても、登録済みの色に対する `Remove favorite` は有効にする。
- お気に入りの通常操作として全件削除ボタンは置かない。
  破損・未対応データの復旧時だけ `Reset favorites` を表示する。

## 4. 確認ダイアログ

- ネイティブの `<dialog>` と `showModal()` を使用し、アプリに合わせた見た目にする。
- タイトル、影響範囲、`Cancel`、実行ボタンを表示する。
- 初期フォーカスを `Cancel` に置く。
  Escape で閉じた場合もキャンセルとして扱う。
- 背景クリックだけで削除を確定しない。
- 確定後も保存が失敗した場合は成功扱いにしない。
  ダイアログを閉じ、元の一覧とエラーを表示する。
- 閉じた後は起点の操作へフォーカスを戻す。
  起点が削除された場合や無効になった場合は、その一覧の見出しへ戻す。

| 操作                   | タイトル           | 実行ボタン        | 説明する影響                                                     |
| ---------------------- | ------------------ | ----------------- | ---------------------------------------------------------------- |
| 履歴全件削除           | `Clear history?`   | `Clear history`   | 対象の履歴を削除する。表示色とお気に入りは残る                   |
| お気に入り解除         | `Remove favorite?` | `Remove favorite` | 対象の HEX を示す。表示色と履歴は残る                            |
| 破損履歴の初期化       | `Reset history?`   | `Reset history`   | 読み込めない履歴データとタブ内の履歴を削除する。お気に入りは残る |
| 破損お気に入りの初期化 | `Reset favorites?` | `Reset favorites` | 読み込めないお気に入りデータを削除する。履歴は残る               |

確認中に別タブで対象が変更される可能性があるため、確定時に保存処理側で最新状態を再確認する。
既に削除されたお気に入りを再作成しない。
Reset の確認中に保存値が変わった場合は削除せず、再読み込みして最新内容を確認するよう案内する。

## 5. 状態と操作可否

| 状態                     | 表示                                                         | 利用できる操作                                                             |
| ------------------------ | ------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 初回生成中               | 色のプレースホルダー、`Generating...`                        | 読み込んだ一覧の閲覧。色に依存する操作は無効                               |
| 通常                     | 色、コード、日時、一覧                                       | 生成、コピー、一覧の選択、保存操作                                         |
| 次の色を生成中           | 直前の色を保持し、`Generating...` を表示                     | 閲覧、詳細の開閉、現在のコードのコピー。生成・表示切り替え・保存変更は無効 |
| 初回生成失敗             | エラー、色がない状態                                         | 再生成。保存済み一覧がある場合は選択して表示できる                         |
| 次の生成に失敗           | 直前の色、エラー                                             | 再生成と通常の操作                                                         |
| 履歴保存不可             | 保存できないことを示す継続的な案内                           | 色の生成とタブ内の履歴利用。再読み込み後の保持を約束しない                 |
| お気に入り保存不可       | 保存失敗の案内、直前の一覧                                   | 一覧の閲覧・再表示。失敗した追加・解除を反映しない                         |
| 保存データの破損・未対応 | 対象を明示した案内、`Reset history` または `Reset favorites` | 他の正常な機能、対象領域の確認付きリセット                                 |

- 生成中は削除・リセットを含む保存内容変更の入口を無効にする。
- 保存状態は履歴とお気に入りで別々に表示する。
  片方の失敗だけで、正常なもう片方を使用不可にしない。
- 破損保護中の履歴はタブ内で利用できるが、通常の `Clear history` は無効にし、保存データの削除は確認付きリセットに集約する。
- 詳細や一覧の開閉状態は、生成の成功や別タブの一覧更新では変更しない。

## 6. 通知と保存に関する説明

### 6.1. 通知

- コピー成功と保存案内には `role="status"`、生成・コピーなどのエラーには `role="alert"` を使用する。
  同じ内容の重複を避ける場合は、ライブ領域を付けない指定も持つ。
- 通知には `Success` / `Error` / `Storage notice` の種別と内容を表示する。
- 生成失敗や保存失敗は、原因と次にできる操作が分かる英語で表示する。
- 同じエラーを複数のライブ領域で繰り返し読み上げない。
- 操作結果と、履歴・お気に入りそれぞれの保存案内を分けて表示する。
  両領域の調整や障害が同時にあっても、一方の案内で他方を隠さない。
- 通知は時間経過で自動消去せず、後続操作や状態更新で必要な内容へ切り替える。
- 技術的な例外の全文やスタックトレースを UI に表示しない。

| 場面                     | メッセージ                                                                                                       |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| コピー成功               | `HEX copied.`                                                                                                    |
| コピー失敗               | `Could not copy. Select the code and copy it manually.`                                                          |
| 生成失敗                 | `Could not generate a color. Please try again.`                                                                  |
| 履歴保存失敗             | `History could not be saved. New history is available in this tab until you reload.`                             |
| お気に入り保存失敗       | `Could not save favorites. Your favorites were not changed. Check your browser settings or reload to try again.` |
| 一部の保存記録を除外     | `Some saved history entries were skipped or adjusted.`                                                           |
| 履歴データの破損・未対応 | `Saved history could not be read. Reset it to enable saving again. New history is available only in this tab.`   |

お気に入りの調整案内では `history` を `favorites` にする。
お気に入りの破損保護では `Saved favorites could not be read. Reset them to enable saving again.` と表示する。
タブ内履歴だけを削除した場合は `History in this tab cleared. Saved history was not changed.` とし、保存済みデータを削除したと案内しない。
別タブで解除済みの場合は `This favorite was already removed. No changes were needed.` と案内する。
生成・表示切り替え・コピー・保存操作が進んだ後に、古いコピー完了で通知を上書きしない。

### 6.2. 保存に関する説明

画面の下部に、次の説明を表示する。

> History and favorites are saved in this browser and may be lost if browser data is cleared. This app does not send generation records to external services.

実装方式の詳細や `localStorage` の仕組みを利用手順へ持ち込まない。

## 7. アクセシビリティとレスポンシブ表示

- `header`、`main`、見出し、一覧、ボタンなどの意味に合った HTML を使用する。
- Tab / Shift+Tab で操作でき、フォーカス位置を視覚的に確認できるようにする。
- ボタンの操作名に対象と処理を含める。
  アイコンだけの操作を避ける。
- 色見本と同時に HEX を表示し、選択・登録・エラーを色だけで伝えない。
- 中立色の背景上で本文とボタンのコントラストを確保する。
  生成色そのものを文字色のコントラスト保証に使用しない。
- 詳細や一覧の開閉、ダイアログをキーボードで操作できることを確認する。
- スマートフォン幅でも操作ボタンが重ならず、長いハッシュを含めてページ全体の横スクロールを発生させない。
- 過度なアニメーションを導入しない。
  アニメーションを使用する場合は `prefers-reduced-motion` を考慮する。

## 8. Storybook で扱う状態

Storybook は、コンポーネントの見た目と状態をアプリ本体から分離して確認する学習に使用する。

- 色表示: 固定色、初回の色なし、生成中、長い詳細情報。
- 履歴: 空、記録あり、20 件、同じ HEX の別記録。
- お気に入り: 空、登録済み、20 色、保存不可。
- 通知: 成功、生成失敗、保存不可、破損保護、両領域の調整案内、長い文言。
- 確認ダイアログ: 履歴削除、お気に入り解除、破損データのリセット。

各 Story は固定データとモックのコールバックを使用する。
実際の時刻・ハッシュ生成・ブラウザの保存データに依存させない。
Controls で props を変更し、Actions でイベントを観察できるようにする。

データ処理の正しさは単体テストと E2E で検証する。

## 9. 公開用素材

タブと共有用の画像は、アプリ名と自作の寒色の図形で統一する。
図形はシアン `#22D3EE`、青 `#1D89E2`、青紫 `#7C3AED` の角丸正方形を重ね、文字や細線を使わず小さな表示でも識別できる形にする。
複数の色面はアプリの識別用であり、パレット生成機能を表すものではない。

| 用途                  | 元データ・配信形式                    | 寸法・背景                                       |
| --------------------- | ------------------------------------- | ------------------------------------------------ |
| ファビコン            | [SVG](../../public/favicon.svg)       | 64×64 の座標、背景透過                           |
| ファビコンの fallback | [PNG](../../public/favicon-32x32.png) | 32×32、背景透過。同じファビコン SVG から生成する |
| OGP 原稿              | [SVG](../../assets/site/og-image.svg) | 1200×630、不透明                                 |
| OGP 配信画像          | [PNG](../../public/og-image.png)      | 1200×630、不透明。OGP 原稿から生成する           |

OGP は `#F8FAFC` の背景と白い枠に、英語のアプリ名、画面と同じ短い説明、ファビコンと同じ図形を配置する。
実画面のスクリーンショットではなく、共有用の図案とする。
画像の代替文は `Random Cool Color Generator with cyan, blue, and violet color swatches.` とする。
HTML の theme-color も `#F8FAFC` に合わせる。

素材の参照 URL と再生成方法は [技術設計](03-technical-design.md) に定義する。
