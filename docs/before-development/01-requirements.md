# 要件定義

本書は Random Cool Color Generator の実装開始前の要件を定義する。

実装開始までは計画の調整対象とし、実装開始後は計画時点の記録として保持する。
文書の運用と工程は [開発計画](04-development-plan.md) に定義する。

## 1. 企画と目的

- アプリ名: Random Cool Color Generator
- リポジトリ名: `random-cool-color-generator`
- 年月日を含む生成時点の日時などを入力にして寒色を生成し、画面に表示する小規模な Web アプリケーションとする。
- 主な目的は、React / TypeScript による個人開発と、AI エージェントを利用した計画・実装・検証・ドキュメント作成の実践とする。
- 特定の利用者像、業務用途、利用頻度は設定しない。
  画面を開けば認証なしで利用できる。
- フロントエンドのみで動作し、生成記録とお気に入りは利用中のブラウザに保存する。

## 2. 対象範囲

### 2.1. 実装する機能

| ID   | 機能                     | 概要                                               |
| ---- | ------------------------ | -------------------------------------------------- |
| F-01 | 寒色の生成               | 初回表示時とボタン操作時に寒色を生成する           |
| F-02 | 色と生成情報の表示       | 色見本、HEX、生成日時、詳細情報を表示する          |
| F-03 | カラーコードのコピー     | HEX / RGB / HSL を個別にコピーする                 |
| F-04 | 履歴の保存と再表示       | 直近 20 件を保存し、選択した記録を再表示する       |
| F-05 | 履歴の全件削除           | 確認後に履歴を削除する                             |
| F-06 | お気に入りの保存と再表示 | 最大 20 色を保存し、選択した記録を再表示する       |
| F-07 | お気に入りの解除         | 確認後に対象の色をお気に入りから解除する           |
| F-08 | 保存異常への対応         | 保存失敗を通知し、壊れたデータを無断で上書きしない |
| F-09 | タブ間の一覧更新         | 同じ保存領域を利用する別タブの変更を一覧へ反映する |

### 2.2. 対象外

- 認証・認可、ユーザーアカウント、バックエンド、DB、外部 API。
- クラウド同期、データのインポート・エクスポート、共有 URL。
- 色の手動編集、範囲指定、検索、並べ替え、パレット生成。
- 履歴の個別削除、お気に入りの通常操作による全件削除。
- テーマ切り替え、PWA、オフライン利用の保証、多言語切り替え。
- すべての生成結果の一意性、乱数としての暗号学的な安全性の保証。

## 3. 機能要件

### 3.1. 寒色の生成: F-01

- ページの初回表示時に 1 回生成する。
  React の開発時の Strict Mode でも生成と履歴追加を重複させない。
- 以降は `Generate color` ボタンで生成する。
  時刻に応じた自動更新や定期実行は行わない。
- 入力には、年月日・時分秒・ミリ秒を含む絶対時刻を表す `Date.now()` と、ページ内の生成要求の連番を使用する。
  同じミリ秒の要求も区別する。
- SHA-256 の結果から HSL を求める。
  採用範囲は H: 160〜270 度、S: 65〜100%、L: 25〜70% とし、緑寄りのシアンから青・青紫までを含む本アプリの寒色の範囲とする。
- 生成候補の HEX が現在表示中の HEX と一致する場合は再試行する。
  初回生成時は、読み込めた最新の履歴の HEX と比較する。
- 候補の生成は最大 8 回とする。
  以前の履歴との重複や、見た目が近い色の生成は許容する。
- 正確なシード形式、変換式、再試行条件は [技術設計](03-technical-design.md) に定義する。

### 3.2. 色と生成情報の表示: F-02

- 大きな正方形の色見本、HEX、生成日時を表示する。
- 生成日時は保存した絶対時刻を、表示時のブラウザのローカルタイムゾーンでミリ秒・UTC オフセット付きで表示する。
- `Details` を開くと RGB、HSL、SHA-256 の全文を確認できる。
- 履歴やお気に入りから開いた場合も、元の色と生成記録を表示する。
  新しい日時での生成や再計算は行わない。
- 一覧の選択、履歴削除、お気に入り解除によって、現在の表示色を自動で別の色に置き換えない。

### 3.3. コピー: F-03

- HEX / RGB / HSL を CSS で使用できる形式で個別にコピーする。
- HEX は `#1D89E2` のように大文字で表示・コピーする。
- 成功を画面上で通知する。
  失敗時は手動で文字列を選択してコピーする方法を案内する。
- クリップボードの利用に失敗しても、生成記録や保存状態は変更しない。

### 3.4. 履歴: F-04 / F-05

- 生成が成功するたびに履歴の先頭へ追加し、直近 20 件を保持する。
  超過分は古い順に除外する。
- 日数による期限は設けない。
  ブラウザ側で削除されるまで保存するが、長期保存は保証しない。
- 過去の記録と HEX が同じでも、異なる生成記録として履歴に追加できる。
- 履歴の選択は表示の切り替えのみとし、履歴の追加、並べ替え、生成連番の消費を行わない。
- `Clear history` は確認ダイアログを表示し、承認された場合にのみ履歴を削除する。
- 履歴を削除しても現在の表示色とお気に入りを保持する。

### 3.5. お気に入り: F-06 / F-07

- 現在の表示色と履歴の各記録から、お気に入りへ登録できる。
- 最大 20 色とし、HEX を同一性の基準にする。
  同じ HEX の二重登録は行わない。
- 同じ HEX の別の生成記録を選んでも、最初に登録した元の生成記録を保持する。
- 新しく登録した色を先頭に表示する。
  表示の切り替えで順序を変えない。
- 20 色に達した場合は新規登録を止め、既存のお気に入りを解除するよう案内する。
  自動削除は行わない。
  登録済みの色の解除は可能とする。
- メイン表示、履歴、お気に入り一覧の登録済み表示は、同じ HEX に対して連動する。
- 解除時は対象の色を示す確認ダイアログを表示する。
  キャンセルした場合は変更しない。
- 履歴から消えてもお気に入りを表示できるよう、登録時の生成記録そのものを保存する。

### 3.6. 保存、異常時の動作、タブ間更新: F-08 / F-09

- 履歴とお気に入りを別々の `localStorage` キーに保存し、独立して読み込み・検証する。
- 保存対象は色と生成処理の記録だけとする。
  アプリ内で名前、メールアドレス、位置情報などを収集しない。
- 保存データのうち一部の記録だけが不正な場合は、正常な記録を利用し、除外があったことを通知する。
- JSON 全体の破損、未対応のスキーマ、全件が不正な非空データは、元データを保持し、その保存領域への通常の書き込みを止める。
- 破損・未対応データに限り、確認付きの `Reset history` / `Reset favorites` を表示する。
  削除対象は該当するアプリ専用キーだけとする。
- 履歴を保存できない場合も、現在のタブ内で直近 20 件を利用できるようにする。
  保存できないことを通知し、再読み込みまで保存を再試行しない。
  破損データの明示的なリセットは例外とする。
- お気に入りの登録・解除は、保存の成功を確認してから画面へ反映する。
  失敗した場合は操作前の状態を保持する。
- 保存領域を利用できない状態と、保存内容の破損を区別する。
  利用不可に対して破損データ用のリセット操作を案内しない。
- 正常に保存できる状態では、別タブの変更を履歴・お気に入り一覧へ反映する。
  現在の表示色は各タブで保持する。
- 同時書き込みの厳密な競合解決は行わない。
  完全に同時の更新では後の書き込みが残る場合がある。
- ブラウザを閉じた後も通常は利用できるが、ブラウザ設定、プライベートブラウジング、保存領域の削除などによる消失は許容する。

### 3.7. 処理中と失敗時の共通動作

- 生成中は生成ボタン、履歴・お気に入りからの表示切り替え、保存内容を変更する操作を無効にし、多重実行を防ぐ。
  現在の色の閲覧とコピーは可能とする。
- 初回生成に失敗して表示色がない場合は、エラーと再実行手段を表示する。
- 表示色がある状態で生成に失敗した場合は、直前の色を保持し、履歴に追加しない。
- 成功通知とエラー通知を区別する。
  保存に失敗した操作を成功として通知しない。
- 削除確認は画面内のダイアログで行う。
  `Cancel` を初期フォーカスとし、Escape でもキャンセルできる。

## 4. 非機能要件

| ID   | 項目             | 方針                                                                                                                                   |
| ---- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| N-01 | 画面と言語       | 1 ページ構成とし、UI は英語、開発文書とコードコメントは原則として日本語にする                                                          |
| N-02 | レイアウト       | 白・グレーを基調とし、PC とスマートフォンの両方で操作できる。色見本や長いハッシュで横スクロールを発生させない                          |
| N-03 | アクセシビリティ | キーボード操作、フォーカス、操作名、状態通知を用意し、色だけで状態を区別しない                                                         |
| N-04 | 動作環境         | 最新安定版の Chromium 系ブラウザを主要な検証対象とし、デスクトップ・モバイル幅を確認する。他のブラウザの動作保証は実際の確認範囲に従う |
| N-05 | 配信             | GitHub Pages の HTTPS とローカル開発環境で動作させる。生成・コピーで使用するブラウザ API の失敗を扱う                                  |
| N-06 | 通信             | アプリの色生成・保存処理から外部へ生成記録を送信しない。解析、外部エラー収集、実行時の外部フォント・スクリプト CDN を導入しない        |
| N-07 | 保存の境界       | `localStorage` は機密情報の保管場所やアクセス制御として扱わない。同一オリジンの他アプリと共有されることを前提に専用キーだけを操作する  |
| N-08 | 保守と学習       | 小規模に合う責務分割を行い、単体テスト、E2E、Storybook、CI を用途を分けて利用する                                                      |

ページの取得など、静的ホスティングに必要な通信は発生する。
「インターネット通信が一切ない」とは説明しない。

保存領域やホスティングサービスそのものの永続性・ログ管理を本アプリで保証するものではない。

## 5. 受け入れ条件

| ID    | 条件                                                                                                         |
| ----- | ------------------------------------------------------------------------------------------------------------ |
| AC-01 | 初回表示で 1 回だけ生成し、生成ボタンで次の色を表示する。生成中に多重実行しない                              |
| AC-02 | 固定入力に対する SHA-256 / HSL / RGB / HEX が技術設計の既知値と一致し、範囲・再試行上限を満たす              |
| AC-03 | 色見本とコード、生成日時、詳細を表示し、HEX / RGB / HSL を所定の形式でコピーできる                           |
| AC-04 | 履歴を最新順で 20 件まで保持し、選択しても履歴を追加・並べ替えせず、元の記録を表示する                       |
| AC-05 | 通常の再読み込み後に履歴を読み込める。初回の新規生成 1 件が先頭に追加される                                  |
| AC-06 | お気に入りを HEX ごとに最大 20 色保存し、重複登録・自動削除を行わない。履歴削除後も再表示できる              |
| AC-07 | 履歴削除とお気に入り解除は確認後に行い、キャンセルと Escape では変更しない。現在の表示色は保持する           |
| AC-08 | 保存データを検証し、破損・未対応データを無断で上書きしない。確認付きのリセットは対象の専用キーだけを削除する |
| AC-09 | 履歴保存失敗時はタブ内で利用を続けられる。お気に入り保存失敗時は操作前の状態を保持し、失敗を通知する         |
| AC-10 | 正常保存中は別タブの変更で一覧が更新され、各タブの表示色は保持される                                         |
| AC-11 | 生成・コピー失敗を案内できる。生成失敗時に現在の表示色と履歴を壊さない                                       |
| AC-12 | モバイル幅、キーボード操作、ダイアログ、代表的な画面状態のアクセシビリティを確認する                         |
| AC-13 | 品質チェックと本番ビルドに成功し、公開時に正しいサブパスでアプリが動作する                                   |
| AC-14 | 生成記録を外部リクエストや URL に含めず、保存・削除はアプリ専用のキーだけを対象とする                        |

詳細な検証方法と工程の対応は [開発計画](04-development-plan.md) に定義する。
テストの合格と、目視・操作で確認した範囲を区別して記録する。
